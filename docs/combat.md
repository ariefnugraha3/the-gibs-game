## Campaign economy — loot/money, explosive barrels, horde

**CAMPAIGN ECONOMY = LOOT/MONEY (SECOND-IMPROVEMENT-PLAN points 1-3, 2026-07-22 — see [SECOND-IMPROVEMENT-PLAN.md](SECOND-IMPROVEMENT-PLAN.md)):** killing a robot in **campaign** now gives **NO direct score** — instead it drops **LOOT** (amber credit chips) that **stay where they fall** and, when the player walks over them, add to `score` = the shop currency (Alien-Shooter style: you must LOOT to afford the shop). `killRobot` (robots.js) routes the reward through the new scene hook **`activeScene.awardKill(z)`**: Survival has no hook → `addScore(robotScore(z))` (unchanged); every campaign stage sets `awardKill: campaignAwardKill` (common.js) → `spawnLoot(x, z, CFG.drops.loot[z.kind])` (drops.js; boss = 8 chips). The tank boss also gives no direct score (killing it = MISSION COMPLETE; final score = looted money). Loot lives in the `drops` array as `type:'loot'` (pickup handled in `updateDrops`; radar shows gold blips). **The magnet was REMOVED on 2026-07-27 (user request): a chip no longer flies toward the player — it spins in place at its drop point until the player walks within `CFG.drops.lootPickupRadius` (raised 6 → 9 to compensate); `lootMagnetMeters`/`lootMagnetSpeed` are gone from the config.** **Campaign and Survival share ONE price list** — the `CFG.shop.campaignPriceMul` scaling was removed on 2026-07-26 (user request); `catalog()` now only hides the Survival-only Monas items when `shopCtx.mode==='campaign'` and never touches `it.cost`. Early-stage affordability is tuned through the loot values (`CFG.drops.loot`) alone. The smoke suite asserts the same money buys the same item in both modes and that the multiplier key stays out of the config. **(#2) EXPLOSIVE BARRELS** (`entities/barrels.js`, new): shootable fuel drums placed in every campaign stage's combat zones (`S{1,2,3,4}_BARRELS` + `placeBarrels()` per stage, cleared/replaced each `enter()` via `resetBarrels`) — shot to 0 HP → AoE explosion (`CFG.barrels`) that kills robots in radius AND hurts the player if close (`queueBoom(...,hurtPlayer:true,...)`), with **chain reactions** (`explodeAt` → `detonateBarrelsInRadius`). Barrels are solid to the PLAYER only (`resolveBarrelBlock` in each stage's `playerCollide`), NOT baked into nav (robots walk past → cluster near them = shoot for a satisfying chain). Hit-tested by `barrelBulletHits()` + pulsed by `updateBarrels(dt)` in `updateGame` (empty/no-op in Survival). **(#3) HORDE/SWARM** (`spawnSwarm` in common.js, reusable): a config-driven flood of class-C robots that spawn **immediately `'chasing'`** (`spawnCampaignRobot(...,active=true)`) — wired into Stage 1's post-download "hostiles inbound" beat via `spawnStage1Horde()` (`CFG.campaign.stage1.hordeCount`).

## Robots — classes, rig, AI, attacks

**Robots:** procedural **MACHINE frames** (`buildRobotMesh(cls)`, **overhauled 2026-07-12 from the stylized-human zombie bodies to actual robots**): tapered-cylinder frame torso + class-colored armor chest plate, ball hip/elbow joints, piston limbs, a sensor-drum head with a **glowing emissive visor (the "eyes") + power core** — the **VISOR/eyes are RED for ALL classes** (`EYE_RED` 0xff2020, user request 2026-07-14; the antenna tip too), while the **power core** stays the class color (`CLASS_LOOK.glow`: **C green / B yellow / A red / boss dark-purple**) so class is still readable via the chest core + armor plate (`CLASS_LOOK.armor`), a power backpack, and per-arm tips — **claw hands for melee (C/boss), a right ARM CANNON + head antenna for ranged (B/A)**. Shared `RG` geometries (built once via `geo.scale()` baking) + per-instance Lambert materials (emissive visor uses the same Lambert program — no new shader); never dispose `RG`. The old profession variants/skin tones and `tintRobot`/`applyClassTint` were deleted — class color is built in (boss too). `disposeRobot` still handles array materials defensively. **The animation rig contract is UNCHANGED** — same pivot groups (`inner`, hip/knee/shoulder, `headG`) at the same positions/heights, so `animateRobotRig` is byte-identical and gore.js reads the same rig. **Robot CLASSES** (2026-07-12, `CFG.robot.classes` — REPLACED the old runner/brute/exploder variants, which were deleted): every non-boss robot is one of three classes (`z.kind` = `'C'`/`'B'`/`'A'`), each stamping `hp`/`speed`/`armor`/`attack`/`ranged`/`scale` (+ `rangeMeters`/`fireDelaySec`/`bulletSpeed` for ranged) onto the robot at spawn — **C** (HP 60, slowest, melee claw, attack 5, **GREEN** armor), **B** (HP 90, slow, **RANGED**, attack 5, range **10 m** (70 u), `fireDelaySec` 1.0 s, `bulletSpeed` 7, **YELLOW** armor), **A** (HP 120, medium speed, **RANGED**, attack 10, range **12 m** (84 u), `fireDelaySec` 1.5 s, `bulletSpeed` 5 — slower but harder-hitting shots, **RED** armor). `armor` is flat damage-reduction applied to bullet & blast damage (`max(1, dmg−armor)`; 0 for all classes now — plumbing for future). **Ranged robots STOP AND SHOOT** (2026-07-12): the scene AI (survival `robotAI` / `campaignRobotAI`) halts a ranged robot at `0.95×z.range` **from its current target — the player AND (survival) Monas** — **when its LINE OF FIRE is clear** and faces it; the shared attack branch in robots.js fires via `fireRobotBullet(z, tx?, ty?, tz?, monasDmg?)` every `fireDelaySec`, gated by `z.losOK` (stamped each frame — no shooting through walls) + `res.chaseDist < z.range`.

> **LINE OF FIRE != LINE OF WALK (bugfix 2026-07-27, user report).** Both scene AIs used to gate this on `aim.direct` — the NAV-GRID LOS, swept at the robot's body radius. The nav grid bakes FURNITURE (tables, cupboards) and survival trees/fountain, none of which block a bullet, so a class A/B robot standing behind a table decided its shot was blocked and started pathing AROUND the table like a melee C — instead of standing still and shooting over it. A carries TWO rifles (both arms) and fires them ALTERNATING left/right** (`z.fireSide` toggles per shot inside the same `fireDelaySec` cadence; enemy bullets spawn from the firing barrel's muzzle — `rig.muzzle` right / `rig.muzzleL` left, never from the body). **Shooting animation (2026-07-12): ranged arms HANG at the side while walking and RAISE to aim** (`z.aiming` set by the scene AI when stopped-in-range with clear LOS; lerped via `z.aimT` in `animateRobotRig` — B raises ONLY the right arm, the left keeps swinging low; A raises both), and each shot kicks the firing barrel UP briefly (`z.recoilT`/`z.recoilSide` recoil, replacing the old claw-swipe overlay that looked like a downward scratch — `fireRobotBullet` no longer sets `clawT`). **Enemy bullets** live in the `enemyBullets` array (state.js, small BLUE plasma `MAT.enemyBullet`, scale 1.05; a 6th entity type): `updateEnemyBullets(dt, step)` (called in `updateGame` right after `updateRobots`) moves them, swept-hit-tests the PLAYER (`segPointDist2`; dodge i-frames or an already-dead player = the bullet whiffs, while **god-mode shows the full hit feedback — RED blood + flash — and only skips the HP loss** [2026-07-12 fix: the blood/flash used to sit inside the god-mode guard, so bullet hits never bled] — **a hit sprays RED player blood via `spawnBloodBurst(..., PLAYER_BLOOD_HEX)`**, also at the claw & boom damage sites; player HP 0 → `startPlayerDeath()`, never an instant overlay), and kills them on walls/Monas via `activeScene.bulletBlocked` — **a bullet carrying `monasDmg` (fired AT Monas) that dies on a wall calls the optional scene hook `enemyBulletHitMonas(dmg, pos)`** (survival: ground-puff spark + `damageMonas`). Melee class C & the **boss** (`CFG.campaign.bosses.giant`, still melee: grenades deal the reduced `bosses.giant.grenadeDamage`, tested by `z.kind === 'boss'` in effects.js) claw as before. Survival rolls the class per spawn (`classBFromWave` 3 / `classAFromWave` 6, chances rising per wave, dijepit Max); Campaign grunts are class C (`spawnCampaignRobot(x,z,stage,cls='C')`; stages 2 & 3 mix in some B/A shooters at marked spots). The `pendingBooms`/`queueBoom` blast queue now serves ONLY the Grenade Launcher round (exploder removed, so its `hurtPlayer` branch is currently dead). Scaled robots MUST get `reachMul` from `reachForScale(scl)` — their scaled body-block radius otherwise pushes the player out of their own claw reach. Rig animated by direct `rotation.x` on pivots (`animateRobotRig`). **No damage feedback by design** (player must not see how hurt a robot is). **Damage is a numeric model (rebalanced 2026-07-07):** each bullet carries its weapon's `damage` (rifle 40 / pistol 25 / shotgun 10-per-pellet, × the shop upgrade level — see Weapons), robots have real HP (per class: C 60 / B 90 / A 120), grenades deal `grenade.damage` 100, player HP is 100. **No headshots (removed with the top-down pivot 2026-07-11):** every bullet deals its flat `damage` wherever it lands. **The bullet-vs-robot hit test is HORIZONTAL (2D, xz-plane) — the y dimension is intentionally dropped** because aiming is horizontal-only and all entities stand on the ground; a 3D sphere test let short hitboxes (historically the small scale-0.75 runner variant) slip UNDER the barrel-height (~7.65) bullet path and be unhittable point-blank. The hitbox is effectively a vertical cylinder of radius `bodyHitRadius` 5 × `z.scl` (class C 1.0 / B 1.1 / A 1.2 / boss 2.4); the swept segment (prev→current, projected to xz, spawn frame from the player center) still prevents point-blank/low-fps tunneling. Survival robots jump the fence (two-phase `jumping`→`chasing`, arc reused for the fountain vault); campaign robots start `'idle'` (a class-specific **IDLE** animation — `animateRobotIdle`, 2026-07-14, reworked same day to the user's spec: **BODY & LEGS stay STILL** (all damped to neutral — no hopping/rocking); only the HEAD and ARMS move. **All classes:** the head looks left-right (celingak-celinguk, scanning surroundings, `head.rotation.y`). **Per-class gesture** (periodic, randomized timing): **C** occasionally raises & lowers both claw-hands; **B** occasionally RUBS its rifle with the free left hand (reaches across + wipes back-and-forth); **A** occasionally JUGGLES its right rifle — tosses it up spinning and catches it (the exposed `rig.gunR` gun group arcs up via `position.y` + two `rotation.x` flips, returning exactly to the hand). Shootable, solid) and wake by distance (`activateMeters`×7) + stage-1 grid LOS, or when shot; on waking, the non-idle path damps out the residual head-scan (`head.rotation.y`) + lean (`inner.rotation.z`) and snaps a mid-juggle rifle back to the hand. **Chasing uses the pathfinder** (`utils/pathfind.js`, added 2026-07-06): each scene bakes a nav-grid once (survival: Monas+trees blocked, fountain deliberately walkable so the vault still triggers; stage 1: half-cell 7-unit grid — walls from the floor-plan grid PLUS furniture/stair blockers baked via resolve, so robots route around desks instead of shoving them; stages 2 & 3: same half-cell grid engine as stage 1, furniture/void baked via resolve). `navAim` checks grid-LOS **every frame** (cheap) and returns a shared `{x, z, direct}` — direct chase the instant the player is visible, waypoint steering the instant the line is blocked (no timer lag; only `findPath` is rate-limited by `CFG.robot.repathSec`, forced when stuck > `stuckSec`); waypoints also advance early when the next one is visible (runtime string-pull). Movement runs along a turn-rate-limited heading (`turnToward`, `CFG.robot.turnRadPerSec`) so robots curve smoothly instead of snapping between waypoints. Path failure/off-grid falls back to straight chase. Robots no longer wedge against walls/trees/Monas. Claw attack (melee classes) — **0.5 s WINDUP since 2026-07-13, damage is NOT instant on touch**: reaching claw range only STARTS an anticipation (`z.windT = CFG.robot.clawWindupSec`, `z.windTarget` 'player'/'monas'; `attackCd` is set at INITIATION so the 1-per-`clawCooldownSec` cadence is unchanged, just shifted); a central windup ticker in `updateRobots` (runs BEFORE the attack branch and keeps ticking even if the robot's target flips mid-windup) resolves it: swoosh SFX + strike anim start, then the player's distance is RE-CHECKED against `clawRange + clawStrikeGrace` (× reachMul) — backing off or dodging during the windup makes the claw WHIFF — while a Monas-targeted bite lands through the optional scene hook `monasGnawHit(z)` (survival → `damageMonas`; the commit/lock roll stays at initiation). The rig plays a **3-phase attack** (`animateRobotRig`, overhauled 2026-07-13, replacing the old one-arm sine swipe): ANTICIPATION (attacking arm cocks high behind with a strain TREMOR, other arm counters low, torso twists toward the arm + leans back, crouch coil, head tucks to aim — the readable telegraph), STRIKE (cubic ease-in explosion: ~183° diagonal slash across the body, torso whips forward with an `inner.position.z` LUNGE), RECOVERY (smoothstep settle; residual twist/lunge/head-tuck decays smoothly outside attacks — walk/standing never write `inner.rotation`; the dormant `'idle'` state early-returns to `animateRobotIdle` before this claw code). damage = the class `attack` stamped as `z.clawDmg` (C 5; ranged B/A claw only exists as a fallback since they shoot instead), `clawCooldownSec` 1 per robot (boss claws 60 — the windup telegraph applies to the boss too, Monas gnaw `monasClawDamage` 20; against the player's 100 HP); attacking robots stand still (walk cycle damps out).

## Ranged robot fire — class A & B (sharpened 2026-07-27)

The shot itself was fine; the *presentation* was a static aim pose plus one sine bump on the arm. Read from the top-down camera it looked like a statue emitting a ball. Five changes, all in `animateRobotRig`'s ranged branch plus `fireRobotBullet`:

- **A muzzle flash — there was none at all.** The plasma ball simply appeared out of the air. A fixed pool of 10 additive planes (`spawnMuzzleFlash`, effects.js) is laid flat facing up, exactly like the player's, placed at the world position of whichever barrel fired and rolled randomly so no two look alike. Class A flashes bigger than B. It is **deliberately without a PointLight** — the light count must stay constant (the no-recompile invariant), so its brightness comes from additive blending plus bloom. Lifetime ~70 ms; it decays inside `updateExplosions` so the `updateGame` block order gains nothing new, and it's borrowed during `warmupAll` so its texture uploads at load rather than on the first robot shot.
- **Aim lock.** In the last 0.3 s before firing, the breathing sway damps 85% and the eye brightens — the barrel visibly steadies. That's a readable tell to break line of sight, and it costs nothing: `z.fireCd` already existed.
- **Damped recoil** replaced the single sine bump: `0.46·e^{-5.5u}·cos(15u)`. The barrel snaps up, crosses back **past** the aim line, and rings down. (The smoke test asserts exactly that two-sided crossing — counting direction reversals wasn't enough, because the breathing sway produces those on its own.)
- **The body absorbs the shot.** Torso drives backward, twists *away* from the barrel that fired (so class A visibly rocks left/right as it alternates), head jolts up. This is written **after** the claw chain, because for ranged robots that chain always falls into its damping branch and would erase anything written earlier.
- **A firing stance.** Legs spread with knees bent while aiming and the torso leans into the gun. Previously the legs damped straight and the whole attack happened above the waist.

The eye pulse is snapped back to exactly 1 when it fades: `aimT` decays exponentially and never reaches zero, so without the snap every idle robot sits at an emissive of 1+1e-13 forever.

## Ammo pickups — PER-WEAPON (2026-07-26, user request)

The single `'mag'` drop that refilled EVERY weapon at once is gone. Each weapon now has its own ammo item (`src/entities/ammoPickups.js`): **pistol** (small cartridge box with standing 9 mm rounds), **shotgun** (tray of 12-gauge shells — brick-red hulls + brass heads), **rifle** (a pair of stacked curved banana magazines) and **launcher** (three fat 40 mm grenade rounds in a rack) — deliberately DIFFERENT SHAPES, not recolors, so they read at the top-down camera; each also carries a small emissive label plate in its own color (white / hazard / amber / teal) which the radar blip reuses via `AMMO_KINDS[w].color`. Geo/materials are SHARED and never disposed (the `MAG_GEO` pattern) and all four are warmed in `preload.js`.

Drops are `{type:'ammo', weapon}` in the `drops` array. `spawnAmmoDrop(x, z, w, lifetime?)` places one (stage supplies pass `1e9` = never expires); `spawnMedkitDrop(x, z, lifetime?)` is its medkit twin. Pickup fills ONLY `player[w].ammo` by `CFG.weapons[w].ammoPickup`, capped at `maxAmmoFor(w)`. ## Robot walk cycle (rewritten 2026-07-28)

The chase animation was four lines — hip = a pure sine, knee = `max(0, ∓sin)`, arms mirroring the hips, and a body bob of `abs(sin)`. The user's verdict was *"seperti boneka yang tidak natural"*, and the diagnosis is the same one the player's gait got in July: **the feet were sliding**. At class C's speed the old cadence produced a ~14-unit stride on a 5.7-unit leg — nearly 2.5× the distance the foot could actually cover, so every step scrubbed across the floor. On top of that the knee bent at the wrong moment and the bob pushed the body *up*.

**What changed**

1. **Cadence comes from real speed.** `phase += dt · (10 + speed·10) · gaitVar / mass` puts the stride at ~1.2× the foot's reach instead of 2.4×. The smoke suite asserts this ratio from `CFG.robot.classes.*.speed` and the rig's own hip height, so a speed retune can't quietly reintroduce sliding.
2. **The knee is built from two circular gaussian bumps** (`angBumpR`) instead of a clipped sine: a **deep fold (~1.15 rad) at mid-swing** so the foot clears the ground, and a **shallow absorption (~0.42–0.7 rad) at mid-stance**. It is now nearly straight exactly where it should be — at the plant and at toe-off.
3. **Ankles exist.** `mkLeg` gained an `ankle` pivot (the foot used to be a mesh bolted to the shin), so the foot **pushes off** at toe-off and **flattens** to meet the ground at the plant.
4. **The body drops onto the supporting leg**, twice per cycle, and the depth is *derived from geometry*: `−2.7·(1−cos(kneeStance))` — exactly how much the leg shortens when its knee folds. Inventing a bob amplitude is what buries feet in the floor; tying it to the knee angle keeps contact honest at any tuning, and it is always ≤ 0 (the old `abs(sin)` launched the body upward).
5. **Lateral weight transfer.** The body shifts and rolls toward whichever leg is carrying it. For a two-legged machine this is the single strongest "it has mass" cue from a top-down camera — without it a walk reads as a slide no matter how good the legs are.
6. **Shoulders counter the hips** and the torso **leans into the chase** (`z._gaitLean` / `z._gaitTwist`). These are handed to the claw chain as its *damping target*, so an attack now settles **back into the walk** instead of erasing it — decaying to zero would have wiped the lean every frame.
7. **The head is stabilised** against the bob (55%, same reflex as the player's) and sways gently — the sensor keeps tracking you while the body pounds along underneath.
8. **Banking into turns.** Yaw change per frame is measured and damped into a body roll, so a robot changing direction leans instead of pivoting like a turret.
9. **Per-unit variation.** `gaitVar` (0.88–1.14, assigned lazily on the first animated frame so every spawn path gets it) scales cadence and stride. A pack of twelve no longer marches in perfect lockstep — the thing that most made them read as copies of one puppet.
10. **Footstep audio lands on the footfall.** `animateRobotRig` raises `z.stepPulse` exactly when a foot plants; `player.js` waits for that pulse from the nearest chasing robot instead of firing on a blind 0.55 s timer (still rate-limited to ~3/s, still one sound for the whole horde).

**Stiffened the same day** (user: *"terlalu lincah, coba dibikin agak kaku sedikit"*) — the first pass moved like a sprinting athlete. The fix was to trade cadence for stride and take the springiness out of the joints, not to undo the rewrite:

| | before | after |
| --- | --- | --- |
| steps/sec (class C) | 5.4 | **3.95** |
| hip swing | 34° | **44°** (longer, planted strides) |
| knee fold at mid-swing | 72° | **50°** (leg stays tense) |
| stance flexion → body drop | 0.42 rad | **0.34 rad** (drop shrinks with it, automatically) |
| forward lean, arm swing, head sway | — | all roughly halved |

The hip curve also gained a **`|sin|^0.8` shaping** that flattens the swing peaks, so the leg reaches the end of its stride and *holds* for a beat before reversing — servo, not pendulum. Ankles were stiffened too. The anti-sliding invariant survives all of it: stride is still ~1.35× foot reach, and the smoke suite now *measures* that reach from the animated pose instead of copying the formula, so it keeps holding through future retunes.

Heavier classes get it for free: `mass` (= class scale) slows the cadence and deepens the roll, so B and A stomp where C scurries.

Guarded by the `ROBOT JALAN` / `ROBOT BELOK` / `ROBOT BERHENTI` asserts — stride-vs-reach, knee timing at plant/toe-off/mid-swing, ankle push-off, bob sign and depth, lateral shift direction, head counter-motion, two step pulses per cycle, per-unit variation, banking sign, and every channel returning to neutral when the robot stops. All of them fail on the old curve.

## Collision model — sweeps, hug-and-slide, robot separation

> Extracted from CLAUDE.md on 2026-07-30 when that file was slimmed down again. The short rules stay there; this is the mechanism.

**Collisions are distance checks, not physics.** Robot-hit, pickup and blast all use `distanceTo` radii.

**Bullet-vs-robot is a swept-segment check** (`segPointDist2`, prev→current position). On the spawn frame the segment starts at the player's EYE, so a point-blank shot can never tunnel past the target.

**Survival collision:** Monas is a solid AABB resolved PER-AXIS (`resolveMonas` in survival/world.js — `MONAS_HALF` 22, base 44×44): it hugs-and-slides, it is NOT a full revert, so the player never sticks to the corner — the same fix the campaign walls got. Trees and the fountain are solid cylinders (`resolveObstacles`); the park edge is a fence clamp. **`bulletBlocked` follows the real Monas silhouette height-by-height** — base 44 wide down low, the thin obelisk ~16 wide at eye height, nothing at all above y 64 — so bullets pass through the empty air beside the obelisk and hit robots standing behind it. **Do NOT revert it to a flat 44-wide column**; that was the old behavior and it ate shots that visually had a clear lane.

**Campaign collision:** walkable-union tests (the `stage1Walk` grid / `highwayWalk`) with per-axis `slideWalk` (hug walls, don't stick), plus rotated-AABB `resolveBlockers` for medians, wrecks and furniture — blockers with standable tops are walkable on top.

**Robot bodies are solid to the player only**, pushed out at `CFG.robot.bodyBlockRadius` 7.5 — deliberately *below* the claw-stop distance 8.0, so a robot that has stopped to attack doesn't shove the player away every frame.

**Robots also collide with EACH OTHER** — `separateRobots()` in robots.js, run once per frame at the very end of `updateRobots`, after all movement:

- Any two robots closer than the sum of their separation radii (`CFG.robot.separationRadius` 4.0 × scale) are pushed apart along the connecting line by `CFG.robot.separationRelax` (0.5) × overlap. That is a soft, converging push — no jitter — **not** a hard snap out to the full radius.
- The radius is **kept ≤ half a grid cell's usable width** so two robots still fit through a 1-cell corridor. Raising it past that wedges the pair and blocks the corridor.
- `'idle'` (dormant campaign) robots are **ANCHORS**: they push others but never move themselves. `'jumping'` (fence-vault) robots are skipped entirely — the vault arc owns their position.
- Net effect: robots stop stacking on a single point, and when the player is surrounded the ones that can't fit the front ring get pushed outward and WAIT behind it.
- **Every pushed robot is then re-clamped to walkable space via the `activeScene.clampRobot(z, oldX, oldZ)` hook.** Without it the push shoves robots THROUGH walls: each scene's ordinary per-frame wall-resolve reverts to the frame's *start* position, which the separation push has already moved inside the wall. So `separateRobots` snapshots each robot's valid pre-separation position and passes it as the hug-slide fallback. Implementations: survival = fence clamp + `resolveMonas` + `resolveObstacles`; campaign = `campaignClampRobot` in campaign/utility/common.js (`stage.resolve` furniture + per-axis `stage.walkable` slide).

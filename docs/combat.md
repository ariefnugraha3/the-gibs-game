## Campaign economy — loot/money, explosive barrels, horde

**CAMPAIGN ECONOMY = LOOT/MONEY (SECOND-IMPROVEMENT-PLAN points 1-3, 2026-07-22 — see [SECOND-IMPROVEMENT-PLAN.md](SECOND-IMPROVEMENT-PLAN.md)):** killing a robot in **campaign** now gives **NO direct score** — instead it drops **LOOT** (amber credit chips) that **magnet to the player** and, on pickup, add to `score` = the shop currency (Alien-Shooter style: you must LOOT to afford the shop). `killRobot` (robots.js) routes the reward through the new scene hook **`activeScene.awardKill(z)`**: Survival has no hook → `addScore(robotScore(z))` (unchanged); every campaign stage sets `awardKill: campaignAwardKill` (common.js) → `spawnLoot(x, z, CFG.drops.loot[z.kind])` (drops.js; boss = 8 chips). The tank boss also gives no direct score (killing it = MISSION COMPLETE; final score = looted money). Loot lives in the `drops` array as `type:'loot'` (magnet/pickup handled in `updateDrops`; radar shows gold blips). **Campaign shop prices are scaled by `CFG.shop.campaignPriceMul` (0.5)** — applied in `catalog()` only when `shopCtx.mode==='campaign'`, so Survival prices are untouched; loot values + this multiplier are tuned so the player can't buy everything in early stages (balanced for the planned 13-stage campaign). **(#2) EXPLOSIVE BARRELS** (`entities/barrels.js`, new): shootable fuel drums placed in every campaign stage's combat zones (`S{1,2,3,4}_BARRELS` + `placeBarrels()` per stage, cleared/replaced each `enter()` via `resetBarrels`) — shot to 0 HP → AoE explosion (`CFG.barrels`) that kills robots in radius AND hurts the player if close (`queueBoom(...,hurtPlayer:true,...)`), with **chain reactions** (`explodeAt` → `detonateBarrelsInRadius`). Barrels are solid to the PLAYER only (`resolveBarrelBlock` in each stage's `playerCollide`), NOT baked into nav (robots walk past → cluster near them = shoot for a satisfying chain). Hit-tested by `barrelBulletHits()` + pulsed by `updateBarrels(dt)` in `updateGame` (empty/no-op in Survival). **(#3) HORDE/SWARM** (`spawnSwarm` in common.js, reusable): a config-driven flood of class-C robots that spawn **immediately `'chasing'`** (`spawnCampaignRobot(...,active=true)`) — wired into Stage 1's post-download "hostiles inbound" beat via `spawnStage1Horde()` (`CFG.campaign.stage1.hordeCount`).

## Robots — classes, rig, AI, attacks

**Robots:** procedural **MACHINE frames** (`buildRobotMesh(cls)`, **overhauled 2026-07-12 from the stylized-human zombie bodies to actual robots**): tapered-cylinder frame torso + class-colored armor chest plate, ball hip/elbow joints, piston limbs, a sensor-drum head with a **glowing emissive visor (the "eyes") + power core** — the **VISOR/eyes are RED for ALL classes** (`EYE_RED` 0xff2020, user request 2026-07-14; the antenna tip too), while the **power core** stays the class color (`CLASS_LOOK.glow`: **C green / B yellow / A red / boss dark-purple**) so class is still readable via the chest core + armor plate (`CLASS_LOOK.armor`), a power backpack, and per-arm tips — **claw hands for melee (C/boss), a right ARM CANNON + head antenna for ranged (B/A)**. Shared `RG` geometries (built once via `geo.scale()` baking) + per-instance Lambert materials (emissive visor uses the same Lambert program — no new shader); never dispose `RG`. The old profession variants/skin tones and `tintRobot`/`applyClassTint` were deleted — class color is built in (boss too). `disposeRobot` still handles array materials defensively. **The animation rig contract is UNCHANGED** — same pivot groups (`inner`, hip/knee/shoulder, `headG`) at the same positions/heights, so `animateRobotRig` is byte-identical and gore.js reads the same rig. **Robot CLASSES** (2026-07-12, `CFG.robot.classes` — REPLACED the old runner/brute/exploder variants, which were deleted): every non-boss robot is one of three classes (`z.kind` = `'C'`/`'B'`/`'A'`), each stamping `hp`/`speed`/`armor`/`attack`/`ranged`/`scale` (+ `rangeMeters`/`fireDelaySec`/`bulletSpeed` for ranged) onto the robot at spawn — **C** (HP 60, slowest, melee claw, attack 5, **GREEN** armor), **B** (HP 90, slow, **RANGED**, attack 5, range **10 m** (70 u), `fireDelaySec` 1.0 s, `bulletSpeed` 7, **YELLOW** armor), **A** (HP 120, medium speed, **RANGED**, attack 10, range **12 m** (84 u), `fireDelaySec` 1.5 s, `bulletSpeed` 5 — slower but harder-hitting shots, **RED** armor). `armor` is flat damage-reduction applied to bullet & blast damage (`max(1, dmg−armor)`; 0 for all classes now — plumbing for future). **Ranged robots STOP AND SHOOT** (2026-07-12): the scene AI (survival `robotAI` / `campaignRobotAI`) halts a ranged robot at `0.95×z.range` **from its current target — the player AND (survival) Monas** — **when grid-LOS is clear** (`aim.direct`; blocked LOS = keep pathing closer) and faces it; the shared attack branch in robots.js fires via `fireRobotBullet(z, tx?, ty?, tz?, monasDmg?)` every `fireDelaySec`, gated by `z.losOK` (stamped from `aim.direct` each frame — no shooting through walls) + `res.chaseDist < z.range`. **B carries ONE rifle in the right hand; A carries TWO rifles (both arms) and fires them ALTERNATING left/right** (`z.fireSide` toggles per shot inside the same `fireDelaySec` cadence; enemy bullets spawn from the firing barrel's muzzle — `rig.muzzle` right / `rig.muzzleL` left, never from the body). **Shooting animation (2026-07-12): ranged arms HANG at the side while walking and RAISE to aim** (`z.aiming` set by the scene AI when stopped-in-range with clear LOS; lerped via `z.aimT` in `animateRobotRig` — B raises ONLY the right arm, the left keeps swinging low; A raises both), and each shot kicks the firing barrel UP briefly (`z.recoilT`/`z.recoilSide` recoil, replacing the old claw-swipe overlay that looked like a downward scratch — `fireRobotBullet` no longer sets `clawT`). **Enemy bullets** live in the `enemyBullets` array (state.js, small BLUE plasma `MAT.enemyBullet`, scale 1.05; a 6th entity type): `updateEnemyBullets(dt, step)` (called in `updateGame` right after `updateRobots`) moves them, swept-hit-tests the PLAYER (`segPointDist2`; dodge i-frames or an already-dead player = the bullet whiffs, while **god-mode shows the full hit feedback — RED blood + flash — and only skips the HP loss** [2026-07-12 fix: the blood/flash used to sit inside the god-mode guard, so bullet hits never bled] — **a hit sprays RED player blood via `spawnBloodBurst(..., PLAYER_BLOOD_HEX)`**, also at the claw & boom damage sites; player HP 0 → `startPlayerDeath()`, never an instant overlay), and kills them on walls/Monas via `activeScene.bulletBlocked` — **a bullet carrying `monasDmg` (fired AT Monas) that dies on a wall calls the optional scene hook `enemyBulletHitMonas(dmg, pos)`** (survival: ground-puff spark + `damageMonas`). Melee class C & the **boss** (`CFG.campaign.bosses.giant`, still melee: grenades deal the reduced `bosses.giant.grenadeDamage`, tested by `z.kind === 'boss'` in effects.js) claw as before. Survival rolls the class per spawn (`classBFromWave` 3 / `classAFromWave` 6, chances rising per wave, dijepit Max); Campaign grunts are class C (`spawnCampaignRobot(x,z,stage,cls='C')`; stages 2 & 3 mix in some B/A shooters at marked spots). The `pendingBooms`/`queueBoom` blast queue now serves ONLY the Grenade Launcher round (exploder removed, so its `hurtPlayer` branch is currently dead). Scaled robots MUST get `reachMul` from `reachForScale(scl)` — their scaled body-block radius otherwise pushes the player out of their own claw reach. Rig animated by direct `rotation.x` on pivots (`animateRobotRig`). **No damage feedback by design** (player must not see how hurt a robot is). **Damage is a numeric model (rebalanced 2026-07-07):** each bullet carries its weapon's `damage` (rifle 40 / pistol 25 / shotgun 10-per-pellet, × the shop upgrade level — see Weapons), robots have real HP (per class: C 60 / B 90 / A 120), grenades deal `grenade.damage` 100, player HP is 100. **No headshots (removed with the top-down pivot 2026-07-11):** every bullet deals its flat `damage` wherever it lands. **The bullet-vs-robot hit test is HORIZONTAL (2D, xz-plane) — the y dimension is intentionally dropped** because aiming is horizontal-only and all entities stand on the ground; a 3D sphere test let short hitboxes (historically the small scale-0.75 runner variant) slip UNDER the barrel-height (~7.65) bullet path and be unhittable point-blank. The hitbox is effectively a vertical cylinder of radius `bodyHitRadius` 5 × `z.scl` (class C 1.0 / B 1.1 / A 1.2 / boss 2.4); the swept segment (prev→current, projected to xz, spawn frame from the player center) still prevents point-blank/low-fps tunneling. Survival robots jump the fence (two-phase `jumping`→`chasing`, arc reused for the fountain vault); campaign robots start `'idle'` (a class-specific **IDLE** animation — `animateRobotIdle`, 2026-07-14, reworked same day to the user's spec: **BODY & LEGS stay STILL** (all damped to neutral — no hopping/rocking); only the HEAD and ARMS move. **All classes:** the head looks left-right (celingak-celinguk, scanning surroundings, `head.rotation.y`). **Per-class gesture** (periodic, randomized timing): **C** occasionally raises & lowers both claw-hands; **B** occasionally RUBS its rifle with the free left hand (reaches across + wipes back-and-forth); **A** occasionally JUGGLES its right rifle — tosses it up spinning and catches it (the exposed `rig.gunR` gun group arcs up via `position.y` + two `rotation.x` flips, returning exactly to the hand). Shootable, solid) and wake by distance (`activateMeters`×7) + stage-1 grid LOS, or when shot; on waking, the non-idle path damps out the residual head-scan (`head.rotation.y`) + lean (`inner.rotation.z`) and snaps a mid-juggle rifle back to the hand. **Chasing uses the pathfinder** (`utils/pathfind.js`, added 2026-07-06): each scene bakes a nav-grid once (survival: Monas+trees blocked, fountain deliberately walkable so the vault still triggers; stage 1: half-cell 7-unit grid — walls from the floor-plan grid PLUS furniture/stair blockers baked via resolve, so robots route around desks instead of shoving them; stages 2 & 3: same half-cell grid engine as stage 1, furniture/void baked via resolve). `navAim` checks grid-LOS **every frame** (cheap) and returns a shared `{x, z, direct}` — direct chase the instant the player is visible, waypoint steering the instant the line is blocked (no timer lag; only `findPath` is rate-limited by `CFG.robot.repathSec`, forced when stuck > `stuckSec`); waypoints also advance early when the next one is visible (runtime string-pull). Movement runs along a turn-rate-limited heading (`turnToward`, `CFG.robot.turnRadPerSec`) so robots curve smoothly instead of snapping between waypoints. Path failure/off-grid falls back to straight chase. Robots no longer wedge against walls/trees/Monas. Claw attack (melee classes) — **0.5 s WINDUP since 2026-07-13, damage is NOT instant on touch**: reaching claw range only STARTS an anticipation (`z.windT = CFG.robot.clawWindupSec`, `z.windTarget` 'player'/'monas'; `attackCd` is set at INITIATION so the 1-per-`clawCooldownSec` cadence is unchanged, just shifted); a central windup ticker in `updateRobots` (runs BEFORE the attack branch and keeps ticking even if the robot's target flips mid-windup) resolves it: swoosh SFX + strike anim start, then the player's distance is RE-CHECKED against `clawRange + clawStrikeGrace` (× reachMul) — backing off or dodging during the windup makes the claw WHIFF — while a Monas-targeted bite lands through the optional scene hook `monasGnawHit(z)` (survival → `damageMonas`; the commit/lock roll stays at initiation). The rig plays a **3-phase attack** (`animateRobotRig`, overhauled 2026-07-13, replacing the old one-arm sine swipe): ANTICIPATION (attacking arm cocks high behind with a strain TREMOR, other arm counters low, torso twists toward the arm + leans back, crouch coil, head tucks to aim — the readable telegraph), STRIKE (cubic ease-in explosion: ~183° diagonal slash across the body, torso whips forward with an `inner.position.z` LUNGE), RECOVERY (smoothstep settle; residual twist/lunge/head-tuck decays smoothly outside attacks — walk/standing never write `inner.rotation`; the dormant `'idle'` state early-returns to `animateRobotIdle` before this claw code). damage = the class `attack` stamped as `z.clawDmg` (C 5; ranged B/A claw only exists as a fallback since they shoot instead), `clawCooldownSec` 1 per robot (boss claws 60 — the windup telegraph applies to the boss too, Monas gnaw `monasClawDamage` 20; against the player's 100 HP); attacking robots stand still (walk cycle damps out).

## Weapons

**Weapons:** FOUR weapons via the `WEAPON_DEF` table in weapons.js (all per-weapon visual constants live there): `'rifle'` (displayed **"Assault Rifle"**, modeled after the Pindad SS2-V2 — all-black, carry handle with ADS sight channel, ribbed handguard, skeleton folding stock), `'pistol'`, `'shotgun'` (pump-action, box mag), and **`'launcher'`** (displayed **"Grenade Launcher"**, added 2026-07-11 — a fat 40mm break-barrel; Survival-shop-exclusive, `launcherCost`). **The Grenade Launcher fires ONE explosive round per trigger pull (slow `fireDelayMs`, small `maxAmmo` pool) that EXPLODES ON IMPACT** — the round is a bullet with `b.explosive`/`b.explodeR` (slower `roundSpeed`, no tracer stretch; **the round MESH follows the shop upgrade level (2026-07-16): Lv1-2 = the Mk2 grenade via `buildGrenadeMesh`, Lv3 = a ROCKET via `buildRocketMesh` (grenades.js — olive tube, red warhead nose, cross fins, amber exhaust flame; nose = local +Z, lookAt-oriented along flight dir at spawn; shared lazy Lambert/Basic geo/mat, warmed in preload, `userData.rocket` for tests) matching the avatar's Lv3 shoulder rocket-launcher prop — visual only, damage/AoE/speed unchanged**); it detonates on hitting a robot (`robots.js` hit loop) or a wall/Monas (`bullets.js` `hitWall`) — **never on pure life-expiry** — by QUEUEING an `explodeAt` via `queueBoom(x,y,z,r,hurtPlayer,playerDmg,dmg)` (generalized `pendingBooms` in robots.js, processed after the robot loop = no reentrant splice; launcher booms are `hurtPlayer:false` = friendly **and pass the round's `b.damage` as `dmg` — the AoE damage scales with the shop upgrade level**). Blast radius = the old grenade's (`CFG.grenade.killRadius`+3.5); a null `dmg` falls back to `grenade.damage` 100. (The exploder variant that also used `queueBoom` was removed 2026-07-12 — the launcher round is now the queue's only user.) **Model overhaul 2026-07-10 (shapes only — every muzzle point, weapon position, and ADS sight height is at its old calibrated coordinate; do NOT move them):** rifle = split upper/lower receiver + curved banana mag + ejection-port/selector/trigger/buttpad details; pistol = composite slide with serrations and the SIGHTS RIDING THE SLIDE (same absolute offsets — they move with reload pulls now), full trigger-guard loop, hammer, grip panels; shotgun = sighting rib, barrel clamp, ribbed pump, comb+recoil-pad stock. **`pistolSlide`, `pistolMagMesh`, `sgPump`, `sgMagMesh` are now THREE.Groups** (were Meshes) — the reload rigs only write `.position`/`.rotation` so the animation contract is unchanged; keep it that way. **Hands:** `wrapFinger` helper builds fingers as tangent arc segments that genuinely wrap the handguard/pump/grips. **Rifle/shotgun left hand = OVERHAND grip matching the user's CS-style reference (2026-07-10): back of the hand faces the camera on the near side, four fingers drape OVER the top of the handguard/pump from near to far, thumb tucks along the near-bottom toward the muzzle, bare-skin wrist below — don't flip it back to an under-grip.** Fingerless-glove look: `wrapFinger`'s optional `tipMat` renders the last 2 finger segments in a shared `skin` Phong material (same shader program as the glove — warm-up unaffected); pistol support hand is thumbs-forward along the frame. The left forearm placeLimb endpoints in `updateWeaponVisuals` target the overhand wrist offset (−0.45, −0.75/−0.65, +0.8 from the hand group). (Shotgun firing: `pellets: 10` bullets per trigger pull with extra `pelletSpread`; the launcher fires 1 explosive round; rifle/pistol have no `pellets` key = single bullet). **Each weapon has a `damage` in `CFG.weapons.<w>` (rifle 40 / pistol 25 / shotgun 10-per-pellet / launcher 100 AoE); the value — × the weapon's Survival-shop UPGRADE level via `weaponDamage(w)` (weapons.js, 2026-07-12: `player.weaponLvl` 1..`maxWeaponLevel` 3, each level +`upgradeDamagePct` 25% of base → Lv2 125%, Lv3 150%; levels reset per run in `configurePlayer`) — is stamped onto every bullet at spawn (`b.damage`) so the hit-test in robots.js applies the right amount even after a weapon swap (fallback `CFG.weapons.bulletDamage`); the launcher round's leveled `b.damage` also rides `queueBoom → explodeAt(pos, r, dmg)` so its blast scales too (boss `grenadeDamage` override unaffected).** **MAGAZINE SYSTEM REMOVED (2026-07-11):** each weapon is ONE ammo pool — `player[w].ammo`, capped by `CFG.weapons.<w>.maxAmmo` (**rifle 500 / pistol 150 / shotgun 300**), starts FULL, refilled by ammo drops (`+CFG.weapons.<w>.ammoPickup` per owned weapon, the old 'mag' drop type/mesh reused) and the shop's Replenish All Ammo (sets to max). There is **NO reload**: R is unbound, `startReload()` is a kept-but-no-op export, `player.isReloading` is never true (the reload keyframe rigs, reload SFX cancel plumbing, and `reloadMul`/`reloadDurMs` fields are all dormant — don't re-wire them), no auto-reload, and an empty pool gives the dry-fire click. `magSize`/`startMags`/`maxMags`/`reloadMs` were removed from gameplay.json. **Any mention of mags/magazines/reload elsewhere in this file is historical.** Different fire delay/SFX/rig per weapon. **Top-down (2026-07-11): the FPS viewmodel rigs live hidden in `fpsHolder` (logic/timers still drive them — harmless); the VISIBLE gun is the avatar's compact rifle prop, `attachMuzzle` always points `muzzlePoint` at `avatarGunTip` (muzzle flash light + a flat, upward-facing flash sprite are parented there; per-weapon `muzzleScale` still applies), bullet spread is horizontal-only, and the FPS camera recoil kick was removed (aim yaw is cursor-driven).** **BULLET RANGE = THE CURSOR (2026-07-16): every player bullet is stamped `maxDist` (horizontal pivot→`aimPoint` distance at fire time) + its firing point `sx/sz`; `updateBullets` clamps the bullet EXACTLY at that boundary (overshoot backed off along `b.dir`) and marks it `b.ended` — it is removed the NEXT frame, so the final segment still gets the robot sweep (a robot standing right at the cursor is still hittable). ## Gore

**GORE (`entities/gore.js`, 2026-07-11; re-themed GREEN COOLANT 2026-07-12):** robots don't vanish on death — `killRobot(i, {cause,dirx,dirz})` **splices the robot from the live `robots` array FIRST** (so the wreck is inert: no AI/claw/body-block/bullet-hit and it doesn't hold up the survival wave-clear check), awards score, then **hands the robot's own mesh to `spawnCorpse`** (a topple animation about the feet → brief lie → fade [materials flipped `transparent`, no recompile] + slight sink → dispose ~1.7 s) and flings **gibs** (`gibRobot` hides limb pivots on the wreck and throws chunks colored per that limb's armor plate — machine scrap, default tone `0x3d444c`). Robots "bleed" **GREEN COOLANT**, the player bleeds **RED** (2026-07-12): the splat sprite texture (effects.js) is NEUTRAL white and tinted per-spawn via `material.color` — default `COOLANT_HEX` green, player-damage sites pass `PLAYER_BLOOD_HEX` red through the trailing `color` param of `spawnBlood`/`spawnBloodBurst`; the ground `spawnBloodDecal` puddle texture/tint (gore.js, default `0x2fbf66`) stays green (robot-only) — the function names kept their `Blood*` names, only the theme changed. **`cause: 'explosion'` = extra-gory dismemberment** (2× omnidirectional [360°] coolant bursts ~52 sprites, the 5 limb gibs PLUS ~10 extra metal-scrap chunks, and ~9 coolant puddles SCATTERED around the blast + one per gib landing); **`cause: 'melee'` (player sword kill, 2026-07-13) = the robot is CUT IN HALF at the waist**: `bisectCorpse` (gore.js) neutralizes the inner pose then reparents every `inner` child at local y ≥ 6.3 (torso/chest/core/pack/shoulders/neck/head/both arms) into a NEW top-half group whose origin sits exactly ON the cut plane (local y 6.35 — scale-independent, works for the boss too) — the top half is FLUNG tumbling (waist-pivot world-axis quaternion spin) toward aim + blade-travel-left, DRIPPING coolant every 0.06 s until it lands (+decal), while the legs+pelvis (the ORIGINAL group) keep STANDING 0.5–0.85 s with slowly buckling knees and a GUSHING stump, then topple like a normal corpse; both cross-sections get glowing orange CUT-EDGE discs (shared `CUT_GEO` circle + per-wreck Lambert-emissive clones = the robot-visor shader program, zero recompiles), both halves fade/sink together and the robot's materials (SHARED across the halves — collected uniquely from both trees) are disposed ONCE (internal `bisected` pool, cleaned by `resetGore`);
